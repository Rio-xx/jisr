# التوثيق التقني — جسر

## البنية

التطبيق واجهة ويب ثابتة تعمل بالكامل في المتصفح، ومقسمة إلى:

- `index.html`: نقطة الدخول، اللغة العربية واتجاه الصفحة من اليمين إلى اليسار.
- `css/styles.css`: نظام الألوان والتخطيط والاستجابة للأجهزة المختلفة.
- `js/app.js`: التفاعل، التصنيف، العرض، والتحقق والحفظ المحلي.
- `assets/screenshots/`: مجلد مخصص للقطات مستقبلية.

لا يتطلب التطبيق إطار عمل أو مكتبات أو خادماً تطبيقياً. يمكن تقديم الملفات عبر خادم ملفات ثابت، كما يمكن استخدام Vite للمعاينة أثناء التطوير.

## تخزين البيانات المحلي

يحفظ التطبيق مصفوفة البلاغات بصيغة JSON في `localStorage` تحت المفتاح `jisr.reports.v1`. يحتوي كل بلاغ على:

- `id`: رقم فريد للبلاغ.
- `department`, `equipment`, `equipmentNumber`, `description`, `reporter`, `extension`: بيانات البلاغ.
- `risk`, `replacement`: إجابات السلامة وتوفر البديل (`yes` أو `no`).
- `createdAt`: وقت إنشاء البلاغ بصيغة ISO.
- `status`: الحالة الحالية.
- `statusEvents`: سجل زمني للحالات، مع وقت كل تغيير.
- `replies`: ملاحظات وردود الهندسة الطبية وأوقاتها.
- `priorityOverride`: أولوية يدوية أو `null` عند استخدام التصنيف التلقائي.

تُنشأ ستة بلاغات تجريبية عند أول تشغيل فقط. تغيير الحالة أو الأولوية أو إضافة رد يحفظ فوراً محلياً. حذف بيانات الموقع من المتصفح يعيد بيانات العرض التجريبية.

## قواعد التصنيف

تظهر النتيجة وشرح القاعدة للممارس قبل الإرسال:

1. خطر على الرعاية أو السلامة = نعم، ولا يوجد جهاز بديل = **حرج**.
2. خطر على الرعاية أو السلامة = نعم، ويوجد جهاز بديل = **متوسط**.
3. خطر على الرعاية أو السلامة = لا = **منخفض**.

يمكن للهندسة الطبية ضبط أولوية العرض يدوياً. يحتفظ البلاغ بنتيجته التلقائية الأصلية، ويعرضها منفصلة عن الأولوية الحالية.

## الحالات ومؤشرات الزمن

تتقدم الحالة بالتسلسل المحدد: **جديد ← تم الاستلام ← قيد الإصلاح ← بانتظار قطع غيار ← تم الإصلاح**. يُضاف طابع زمني عند كل انتقال. تحسب لوحة الهندسة الطبية البلاغات المفتوحة، ومتوسط الزمن من الإرسال إلى الاستلام بالدقائق للبلاغات المستلمة، ومتوسط الزمن من الإرسال إلى الإصلاح بالساعات للبلاغات المكتملة. تعرض القائمة الأحرج أولاً ثم الأقدم داخل كل أولوية، وتدعم التصفية حسب الحالة والقسم.

## الحدود والخصوصية

هذا نموذج أولي محلي، وليس نظام تشغيل سريري أو نظام تنبيه. لا توجد مزامنة بين الأجهزة، ولا حسابات مستخدمين أو صلاحيات فعلية أو اتصالات خلفية. بيانات العرض مشتركة بين دوري الممارس والهندسة على المتصفح نفسه، ويمكن تعديلها من أدوات المطور. لا تضمن `localStorage` النسخ الاحتياطي أو التوفر الدائم؛ لذلك لا ينبغي الاعتماد عليه لإدارة بلاغات تشغيلية حقيقية.

## اتجاه مستقبلي للخادم وواجهة API

عند الانتقال إلى استخدام مؤسسي، يمكن استبدال طبقة `localStorage` بخدمة API موثقة ومحمية، وإضافة تخزين مركزي وسجل تدقيق غير قابل للتلاعب، ومصادقة وصلاحيات حسب الدور، ومزامنة وتحديثات آنية، وسياسات احتفاظ ونسخ احتياطي، وتسجيل أحداث موثوق. ينبغي إجراء مراجعة أمنية وخصوصية واعتماد سريري قبل إدخال بيانات تشغيلية. لا يرسل الإصدار الحالي أي طلبات API.
